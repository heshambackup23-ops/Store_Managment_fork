# توافق Android

يستهدف Kotlin الإصدار `v1` من خلال Retrofit، ويخزّن التوكن في `SecureTokenStore`. يعيد Worker استخدام المسارات `/api/v1/auth/token` و`/api/v1/me` مع `username` و`device_name` لبنية دخول Kotlin. يطابق توكن الدخول الحقول `access_token` و`token_type` و`expires_at` و`user`، ويمكن إلغاؤه عبر `DELETE /api/v1/auth/token`.

يتصل إصدار `staging` افتراضيًا بعنوان Pages التجريبي عبر HTTPS. يرسل العميل `X-Store-Client: android` لاختيار تمثيل Retrofit عند استخدام توكن Bearer. للتقييم على الجهاز، شغّل تهيئة مستخدم باسم دخول ثم اطلب إصدار التوكن وفحص `me` وإلغاءه.

توجد مواءمة HTTP لقراءة الكتالوج والتصنيفات والعملاء والإشعارات، ولفواتير وأقساط وديون شخصية وموردين وصيانة ومبيعات المنتج. تشمل عمليات الكتابة المتوافقة إنشاء المنتج وتعديله ورفع صورته، والكاشير، وسداد الفاتورة واسترجاعها بصلاحيات مخصصة. يقارن تعديل رصيد المنتج بلقطة الكمية التي عدلها المستخدم حتى يرفض الخادم تجاوز حركة بيع لاحقة. تبقى صيغ Android للمحافظ والهالك وكتابة بقية الموديولات وZIP/XLSX وPDF ضمن فجوات التوافق. راجع [خريطة المسارات](API_ENDPOINT_MAP.md).

تشغّل GitHub Actions اختبارات Kotlin وتطلب بناء APK تجريبي. اختبارات HTTP تثبت استجابة Worker للحمولات المتوقعة. تجربة التطبيق على جهاز أو محاكي لها نتيجة مستقلة في [سجل الاختبار](TESTING_REPORT.md).
