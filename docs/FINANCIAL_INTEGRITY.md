# سلامة المعاملات المالية

- المبالغ في Worker وSQLite أعداد صحيحة بوحدات العملة الصغرى. تبقى الأسعار التي قرأها الخادم محفوظة في بنود الفاتورة. يسجل SQLite حركات المخزون ويحرس الكمية غير السالبة داخل المعاملة.
- تتضمن الكتابات التجارية التي تستخدم مفتاح محاولة بصمة الطلب وهوية الفاعل وقيدًا فريدًا. يسري الإدخال أو العكس أو السداد كوحدة باستخدام `D1.batch()` وقيود SQL. يُعاد استخدام المفتاح نفسه عند انقطاع الشبكة وعدم حسم الاستجابة.
- ترتبط الدفعات والاسترجاع بالسجل الأساسي، وتؤثر حركة العكس عبر إدخال تاريخي. تثبت قيود المخزون والمحفظة أن المبالغ والكمية تفي بالمتبقي عند التنفيذ.
- تقارير المبيعات تعتمد على فواتير D1 وتفصل المسترجع والدفعات. رصيد مزود المحفظة والصندوق والعمولات قيم منفصلة، وسجلات المحفظة تمثيل داخلي للعمليات.
- إثبات التكافؤ مع MySQL يتطلب عينات تاريخية معتمدة ومطابقة لكل رصيد وفاتورة وذمة. نتائج المحاكاة المحلية مدونة في [سجل الاختبار](TESTING_REPORT.md).

مرجع المعاملات [D1 Database API](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch).
