# مراجعة الأمان

- يستخدم Worker توكنات عشوائية قصيرة العمر، ويخزن تجزئتها، ويعيد تقييم حالة المستخدم ودوره في قاعدة البيانات عند كل طلب. تستخدم الواجهة Cookie من نوع `HttpOnly` و`SameSite`، وتكون `Secure` عبر HTTPS. يفرض التعديل بجلسة المتصفح ترويسة CSRF ويفحص Origin. يستخدم Android توكن Bearer.
- تُحمى كلمات المرور باشتقاق PBKDF2 وملح مستقل وpepper في Worker Secret. حد تسجيل الدخول لكل حساب وعنوان يقلل المحاولات. يلزم قياس CPU في Cloudflare Free قبل قبول هذا الإعداد في بيئة مستضافة. كلمات مرور Laravel القديمة وتوكنات Sanctum تستبدل عند تهيئة الحسابات.
- يرفض الخادم الطلبات غير الصالحة ويفحص الصلاحية قبل إدارة الكتالوج أو إجراء المعاملة. تُسجّل التغييرات الحساسة في D1 مع هوية الفاعل ومرجع العملية، وتُمنع تعديلات دفاتر الحركة التاريخية.
- تتطلب صور المنتجات صلاحيات الكتالوج. تخزين التجربة محدود بالحجم والعدد والصيغ. تنزيل CSV يحتاج `backup.export`، ويعالج حقول النص التي قد تتحول إلى صيغ في تطبيقات الجداول.
- راجعنا مسارات الأسرار والنسخ في لقطة Laravel وبحثنا عن مؤشرات نصية شائعة لمفاتيح خاصة وتوكنات. يوجد `.env.example` وصور منتجات موروثة في `public/uploads`. يقتصر هذا الفحص على لقطة الشفرة والمسارات المقروءة. تحتاج الصور الموروثة والتاريخ الكامل إلى مراجعة مستقلة قبل إعادة استخدامها خارج المشروع.
- ملفات الأسرار وبيانات Wrangler والنسخ وملفات SQL المولّدة مستبعدة من Git. بيانات العرض المستخدمة في الاختبارات اصطناعية.

تبقى حماية الحساب السحابي ومراجعة الوصول، وقياس CPU للمصادقة، والاختبار على HTTPS، واختبار حدود الحصص، ومراجعة توافق Android كاملة ضمن تحقق النشر.
