# تجهيز نسخة MySQL لنقل هلال لإدارة المتجر

جهّز ملف SQL لقاعدة التطبيق الأصلية وحدها، يحتوي على **بنية الجداول والبيانات**، مع تقارير الأرصدة من توقيت مرجعي واحد. نستخدم أول نسخة للبروفة والمطابقة، ثم نحدد نافذة قصيرة لإيقاف الكتابة وأخذ النسخة النهائية بعد نجاح البروفة.

## استخراج الملف

**من phpMyAdmin:** اختر قاعدة هلال ← **Export** ← **Custom** ← **SQL**. اختر كل جداول قاعدة التطبيق، وفعّل تصدير البنية والبيانات واحفظ إلى ملف بترميز UTF‑8. اترك الفلاتر وحدود الصفوف فارغة. سجّل إصدار MySQL أو MariaDB وتاريخ ووقت اللقطة بتوقيت القاهرة. للنسخة النهائية، أوقف الكتابة من الويب والكاشير وAndroid والمهام الخلفية في النافذة المتفق عليها، وصدّر التقارير والقاعدة خلالها.

**من PowerShell، إذا كان الخادم MySQL 8:** شغّل الأمر على الجهاز الذي يستطيع الاتصال بقاعدة البيانات. غيّر اسم المستخدم واسم قاعدة التطبيق إن لزم. سيطلب البرنامج كلمة المرور دون وضعها في الأمر. إذا لم يكن `mysqldump.exe` في PATH فاستخدم مساره الكامل مع `&`.

```powershell
$hilalPrivate = Join-Path $env:LOCALAPPDATA 'HilalMigration'
New-Item -ItemType Directory -Force -Path $hilalPrivate | Out-Null
$hilalDump = Join-Path $hilalPrivate ("hilal-" + (Get-Date -Format 'yyyyMMdd-HHmmss') + ".sql")
mysqldump.exe --host=127.0.0.1 --port=3306 --user=BACKUP_USER --password `
  --single-transaction --quick --no-tablespaces --default-character-set=utf8mb4 `
  --hex-blob --set-gtid-purged=OFF "--result-file=$hilalDump" storemanagement
if ($LASTEXITCODE -ne 0) { throw 'MySQL export failed; do not use the partial file.' }
Get-Item -LiteralPath $hilalDump | Select-Object FullName, Length
Get-FileHash -LiteralPath $hilalDump -Algorithm SHA256
```

إذا ظهر MariaDB في XAMPP فاستخدم phpMyAdmin أو عميل التصدير المطابق له؛ خيار `--set-gtid-purged` خاص بـMySQL. استخدم `--result-file` على Windows لتجنب تغيير ترميز الملف بإعادة التوجيه. خيار `--single-transaction` يعطي لقطة متسقة لجداول InnoDB بشرط عدم تغيير البنية أثناء التصدير؛ نافذة وقف الكتابة تجعل التقارير واللقطة متطابقتين وتغطي الجداول الأخرى. المرجع: [دليل mysqldump الرسمي](https://dev.mysql.com/doc/refman/8.4/en/mysqldump.html).

## ما يلزم للمطابقة

احتفظ بالنسخة في مجلد خاص خارج Git وOneDrive. يكفي إرسال **المسار المحلي**، وإصدار المحرك، وتوقيت اللقطة، وSHA‑256، ومسارات التقارير. لا ترسل ملف `.env` أو كلمات مرور أو مفاتيح أو رموز دخول. نبقي نسخة الاستعادة الأصلية خاصة، ونجهّز من نسخة عمل الحقول التجارية ومعرّفات المستخدمين للربط من دون نقل كلمات المرور والجلسات. إذا كانت الصور أو المرفقات مخزنة خارج MySQL، احتفظ بنسخة منفصلة مع مساراتها النسبية.

| التقرير من المصدر في نفس التوقيت | ما نقارنه |
| --- | --- |
| الفواتير والمبيعات والمرتجعات | العدد والإجمالي والمدفوع والمتبقي، ومراجع الدفعات والمرتجعات الفعلية |
| الأقساط والديون الشخصية | الأصل والمدفوع والمتبقي لكل سجل وارتباط القسط بفاتورته |
| الموردون والمشتريات | الرصيد الافتتاحي والمشتريات والمدفوع والمتبقي لكل مورد؛ إرفاق تخصيص الدفعات عند توفره |
| المحافظ والصندوق | رصيد كل محفظة والصندوق، الرسوم والمصروفات، التحويلات المؤجلة والمبالغ المحصّلة والعكس |
| المخزون والهالك والصيانة | كمية كل SKU، حركات الهالك والتصحيح، وحالة أوامر الصيانة والمدفوع فيها |

بعد استلام الملف نستعيده في MySQL معزولة ونقارن الأعداد والمبالغ بالقرش وكمية كل صنف، ثم نجرب الاستيراد إلى D1 منفصلة. أي فرق أو حركة تاريخية بلا مستند تظهر في تقرير المطابقة للمراجعة. الانتقال للتشغيل الفعلي يأتي بعد إغلاق الفروق وإعادة الاختبار على النسخة النهائية. راجع [خريطة الجداول وأدوات الفحص](DATABASE_MIGRATION.md).

## بروفة النسخة المبنية من GitHub

مسار [بروفة MySQL إلى D1](https://github.com/heshambackup23-ops/Store_Managment_fork/actions/workflows/hilal-mysql-rehearsal.yml) يشغّل ترحيلات Laravel من الأصل `90baabb4b38ae292ea7ef55806145518774991bb` على MySQL 8.4، ويضيف بيانات اختبار، ثم يصدّر SQL ويستعيده إلى قاعدة ثانية. يختبر المستخرج والترحيل إلى D1 معزولة. يحتوي مرفق التشغيل على SQL الاصطناعي وبصمته وتقارير الأعداد والمطابقة. ملف MySQL المبني من الكود لا يحتوي على أرصدة المتجر الفعلية.

لاستخراج ملف مطابقة من نسخة عمل معتمدة، استعد SQL أولًا في MySQL منفصلة على `127.0.0.1`، وسمّ القاعدة `hilal_migration_…`، واستخدم حسابًا للقراءة فقط. من `cloud/api` شغّل الأمر أدناه بعد استبدال وقت اللقطة والمنفذ ومسار المجلد بالقيم المعتمدة. الخيار `--ask-password` يطلب كلمة المرور؛ يمكن تحديد مسار عميل MySQL بـ`--client`. ينتج ملفًا خاصًا خارج Git ويطبع الأعداد والتجزئة دون عرض بيانات الصفوف.

```powershell
node scripts/extract-mysql-snapshot.mjs --schema hilal_migration_restored --port 33069 `
  --user BACKUP_READER --ask-password --source-time-zone Africa/Cairo `
  --cutoff-at 2026-10-31T20:00:00+02:00 --output 'C:\Private\hilal-source.private.json'
```

راجع [دليل الاستعادة المعزولة](LEGACY_BACKUP_RESTORE.md) قبل توليد ملف D1. احتفظ بالأصل والتقارير لربط هويات العملاء ومراجعة الجداول التي تحتاج تحويلًا خاصًا.
