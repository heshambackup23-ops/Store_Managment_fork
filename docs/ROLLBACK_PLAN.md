# النسخ الاحتياطي والاستعادة والتراجع

| الأداة | الاستخدام |
|---|---|
| `/api/v1/backup/catalog.csv` | تصدير كتالوج حتى 500 منتج بصلاحية `backup.export`. يسجل العامل من قام بالتصدير. |
| `wrangler d1 export` | لقطة SQL كاملة للمخطط والبيانات. تحتوي على بيانات مستخدمين وتجزئات وجلسات، وتحفظ في مخزن تشغيل خاص. |
| `node scripts/backup-drill.mjs` | تصدير قاعدة Wrangler المحلية واستعادة اللقطة إلى مساحة مستقلة ثم مقارنة الجداول والمجاميع المالية والمفاتيح الخارجية. |
| D1 Time Travel | استعادة نقطة زمنية بواسطة مسؤول الحساب بعد فحص أثرها على الكتابات الأحدث. |
| سجل التدقيق | يرجع لمراجعة من نفذ العملية وتوقيتها. |

شغّل التدريب من `cloud/api` بعد تهيئة D1 ببيانات اصطناعية. أوقف عمليات الكتابة المحلية أثناء أخذ النسخة ومقارنتها. يحفظ التدريب `store.generated.sql` داخل `cloud/api/backups/` ويطبع SHA-256 وأعداد الصفوف الإجمالية. تحفظ نسخ SQL خارج المستودع وفي مكان خاص.

قبل ترحيل سحابي، سجل نسخة Worker وPages الحالية وخذ لقطة SQL ومرجع Time Travel في حساب العرض. إذا فشل النشر أعد إصدار الواجهة والـAPI المتوافقين من لوحة Cloudflare. إذا تغير المخطط بطريقة غير متوافقة، استعد SQL في قاعدة منفصلة أولًا وتحقق من المفاتيح والأرصدة. بدّل ربط `DB` فقط بعد اختبار النسخة المستعادة. طبّق الخطوة على موارد العرض المسماة في [دليل النشر](DEPLOYMENT_GUIDE.md).

أوقف الكتابة قبل التراجع عن إصدار أضاف معاملات مالية جديدة. احفظ لقطة للحالة قبل الترحيل وأخرى بعد المشكلة، وقارن الدفعات وحركات المخزون وقيود المحافظ. قد يتجاهل Worker الأقدم سجلات جديدة رغم قدرته على الاتصال بالمخطط. إذا سُجلت معاملات صحيحة بعد الترقية، أصلح الإصدار الحالي أو طابق تلك المعاملات قبل استعادة نقطة قديمة.

المراجع [D1 export and import](https://developers.cloudflare.com/d1/best-practices/import-export-data/) و[D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/).
